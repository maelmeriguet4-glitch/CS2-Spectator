# Plan 03-01: Dashboard & Accordion Explanations

## Objective
Créer un tableau de bord des résultats d'analyse dans l'interface principale (`customtkinter`), listant les joueurs et affichant leurs preuves de triche de manière détaillée via un système d'accordéon (déroulant) au clic.

## Design Decisions
- **Vue détaillée (Accordéon)** : Cliquer sur un joueur suspect déroulera un sous-panneau listant les `violation_flags`, les `pills` (ex: `[AIMBOT: Snap 18.5°/tick]`), et les statistiques ML extraites du modèle.
- **Navigation** : Le Dashboard remplacera la vue courante (ou sera injecté dans un onglet `Tabview`) après une analyse de lot.

## Components to Create / Modify
1. **`src/ui/components/dashboard_panel.py` [NEW]**
   - Classe `DashboardPanel(CTkFrame)`: Conteneur principal.
   - Classe `PlayerResultRow(CTkFrame)`: Ligne cliquable affichant le joueur (Nom, SteamID, Verdict, Suspicion Score).
   - Intégrer un mécanisme d'**accordéon** : Au clic sur le bouton "Détails" (ou sur la ligne), on instancie (ou rend visible) un `CTkFrame` sous la ligne contenant les preuves textuelles.
2. **`src/ui/app.py` [MODIFY]**
   - Intégrer `DashboardPanel` dans le flow de l'application.
   - À la réception du message `BATCH_ALL_DONE` via la queue, basculer la vue de `ReplaysPanel` vers `DashboardPanel`, en lui passant la liste des `MatchAnalysisResult`.

## Verification
- Créer un test `test_dashboard.py` (ou l'intégrer à `test_ui.py`) pour vérifier que l'accordéon s'affiche correctement sans crasher.
- Exécuter l'application, parser une démo, et s'assurer que les résultats ML sont bien injectés dans l'interface graphique.
